# Feature Specification: 多语言与多货币支持

**Feature Branch**: `001-multi-lang-currency`

**Created**: 2026-07-25

**Status**: Draft

**Input**: User description: "为 Shopify 主题添加完整的多语言和多货币支持功能"

## User Scenarios & Testing

### User Story 1 — 切换界面语言 (Priority: P1)

一位来自法国的访客进入店铺，看到页面默认显示英文。她通过页面顶部的语言选择器将界面切换为法语，页面自动刷新后所有导航、按钮、产品描述均显示为法语，价格货币保持不变。

**Why this priority**: 语言是可访问性的基础。用户必须先能读懂内容，才会产生购买意愿。

**Independent Test**: 在主题设置中配置 3 种语言（英语、中文、法语），通过语言选择器逐一切换，验证每个页面的所有用户可见文本（标题、按钮、表单、提示信息）是否正确翻译。

**Acceptance Scenarios**:

1. **Given** 店铺配置了英语（默认）和法语，**When** 用户点击语言选择器选择法语，**Then** 页面刷新后所有界面文字显示为法语，URL 包含法语语言标识
2. **Given** 用户在法语模式下浏览商品，**When** 用户切换回英语，**Then** 页面刷新回英语，用户所在页面路径保持不变
3. **Given** 店铺只配置了一种语言，**When** 用户访问店铺，**Then** 语言选择器不显示

---

### User Story 2 — 切换货币 (Priority: P1)

一位中国访客在店铺浏览商品，所有价格默认显示为美元。她通过货币选择器切换为人民币（CNY），页面上所有商品价格、购物车小计、运费自动以人民币重新显示。

**Why this priority**: 价格是购买决策的核心因素。用户需要以熟悉货币理解商品价格，直接影响转化率。

**Independent Test**: 在 Shopify 后台配置 4 种货币（USD、EUR、CNY、JPY），通过货币选择器逐一切换，验证所有价格（产品列表、产品详情、购物车）是否正确显示对应货币符号和金额。

**Acceptance Scenarios**:

1. **Given** 店铺支持 USD（默认）和 EUR，**When** 用户选择 EUR，**Then** 所有价格数值按当前汇率转换并以 € 符号显示
2. **Given** 用户将货币切换为 JPY，**When** 用户将商品加入购物车，**Then** 购物车中价格以 JPY 显示
3. **Given** 用户已登录且上次保存了货币偏好为 CNY，**When** 用户再次访问店铺，**Then** 价格自动以 CNY 显示

---

### User Story 3 — 地理位置自动推荐 (Priority: P2)

一位日本用户首次访问店铺。系统检测到她的 IP 地址来自日本，自动将界面语言切换为日语（如果可用），货币切换为日元（JPY），并在页面顶部显示一条非侵入式提示："我们已根据您的位置为您推荐了语言和货币"，同时保留手动切换的入口。

**Why this priority**: 降低首次访问用户的认知负担。自动化推荐减少手动设置步骤，但必须保留手动覆盖能力。

**Independent Test**: 使用不同国家 IP 访问店铺，验证系统是否正确检测地理位置并自动应用对应的语言和货币推荐。

**Acceptance Scenarios**:

1. **Given** 用户 IP 来自法国且店铺支持法语和 EUR，**When** 用户首次访问店铺，**Then** 页面自动以法语显示、价格以 EUR 显示，并显示一条可关闭的推荐提示
2. **Given** 系统自动推荐了 French / EUR，**When** 用户手动切换为英语，**Then** 系统记录用户偏好，后续访问不再自动覆盖手动选择
3. **Given** 用户 IP 对应国家不在店铺支持的语言/货币范围内，**When** 用户访问，**Then** 使用店铺默认语言和货币，不显示推荐提示

---

### User Story 4 — 偏好持久化 (Priority: P2)

一位德国用户将语言设置为英语、货币保持为 EUR 后关闭了浏览器。第二天她再次打开店铺，页面自动以英语显示，价格以 EUR 显示。

**Why this priority**: 回访用户不应每次都重新设置偏好。持久化减少重复操作，提升老用户浏览体验。

**Independent Test**: 设置语言和货币偏好，关闭浏览器后重新打开店铺，验证偏好是否在回访时保留。

**Acceptance Scenarios**:

1. **Given** 用户之前选择了 English 和 EUR，**When** 用户 3 天后再次访问（同一浏览器），**Then** 语言和货币自动恢复为 English 和 EUR
2. **Given** 用户清除了浏览器数据（cookie/localStorage），**When** 再次访问，**Then** 视为首次访问，使用默认设置或触发地理位置推荐
3. **Given** 用户在不同浏览器/设备上访问店铺，**When** 首次打开，**Then** 偏好不跨设备同步（使用默认设置或地理位置推荐）

---

### User Story 5 — 搜索引擎优化 (Priority: P2)

Google 爬虫抓取店铺页面时，能够通过 hreflang 标签识别同一页面的不同语言版本，在搜索结果中优先展示用户母语对应的页面版本。社交媒体分享链接能正确显示对应语言的标题和描述。

**Why this priority**: 多语言内容需要被搜索引擎正确索引才能触达不同语言潜在客户。SEO 配置错误会导致重复内容惩罚或展示错误语言版本。

**Independent Test**: 使用 SEO 检测工具验证每个语言版本的页面是否正确输出 hreflang 标签和 og:locale 元数据。

**Acceptance Scenarios**:

1. **Given** 店铺有英语和法语两个语言版本，**When** 搜索引擎爬虫抓取页面，**Then** `<head>` 中包含 hreflang 标签（`en`、`fr`）及 `x-default` 回退
2. **Given** 用户分享法语版商品页面到社交媒体，**When** 社交平台抓取元数据，**Then** og:title、og:description 显示法语内容，og:locale 设为 `fr`
3. **Given** 商品 A 存在英语和法语版本，**When** 在 Google 搜索该商品法语关键词，**Then** Google 优先展示法语版 URL

---

### User Story 6 — 无障碍访问 (Priority: P3)

一位使用屏幕阅读器的视障用户在浏览店铺时，能够通过键盘操作语言选择器和货币选择器，听到每个选项的清晰标签，并在选择后获得状态变更通知。

**Why this priority**: 无障碍是包容性设计的基础要求。确保选择器控件对所有用户可用。

**Independent Test**: 使用屏幕阅读器（VoiceOver、NVDA）和键盘导航测试语言/货币选择器的完整操作流程，验证是否符合 WCAG 2.1 AA 标准。

**Acceptance Scenarios**:

1. **Given** 用户使用键盘导航，**When** Tab 到语言选择器，**Then** 选择器获得焦点并显示可见焦点指示器，可通过方向键选择
2. **Given** 用户使用屏幕阅读器，**When** 聚焦到货币选择器，**Then** 播报"货币选择，当前：美元"，选择后播报"已切换至：欧元"
3. **Given** 页面放大到 200%，**When** 查看语言选择器，**Then** 所有文本和选项完整可见，不出现截断或重叠

---

### Edge Cases

- 用户浏览器禁用了 JavaScript 时，语言和货币选择器是否有基本的降级方案？
- 用户选择的语言对应翻译文件缺失部分键值时，系统回退到默认语言还是显示键名？
- Shopify 某个货币的汇率数据获取失败时，价格如何显示（回退到店铺默认货币）？
- 用户在购物车中添加商品后切换货币，已加入商品的价格是否实时更新？
- 语言和货币切换后，用户当前所在的页面状态（如商品图片浏览位置）是否保持？
- 同时切换语言和货币时，页面只刷新一次还是两次？

## Requirements

### Functional Requirements

- **FR-001**: 系统必须提供语言选择器组件，允许用户在店铺配置的可用语言之间切换
- **FR-002**: 系统必须提供货币选择器组件，允许用户在店铺配置的可用货币之间切换
- **FR-003**: 语言选择器必须显示语言的本机名称（如 "English"、"中文"、"Français"），而非当前语言的翻译
- **FR-004**: 货币选择器必须同时显示货币代码和货币符号（如 "USD ($)"、"EUR (€)"）
- **FR-005**: 切换语言后，页面所有用户可见文本（导航、按钮、表单、产品描述）必须更新为对应翻译
- **FR-006**: 切换货币后，页面所有价格必须按汇率自动转换并显示对应货币符号
- **FR-007**: 系统必须检测用户地理位置（通过 IP），并在首次访问时自动推荐对应语言和货币
- **FR-008**: 自动推荐语言/货币时，必须显示非侵入式提示信息告知用户
- **FR-009**: 用户手动更改语言或货币后，系统必须记录偏好，后续访问优先使用已保存偏好
- **FR-010**: 语言偏好和货币偏好必须独立保存，修改一项不影响另一项
- **FR-011**: 偏好存储有效期至少为 30 天
- **FR-012**: URL 必须包含当前语言标识（如 `/zh-CN`、`/fr`），确保不同语言版本有唯一 URL
- **FR-013**: 页面 `<head>` 必须为每种可用语言输出 hreflang 标签及 `x-default` 回退
- **FR-014**: 页面 `<head>` 必须根据当前语言输出正确的 `og:locale` 和 `og:locale:alternate` 元数据
- **FR-015**: 语言选择器和货币选择器必须符合 WCAG 2.1 AA 标准（键盘可操作、屏幕阅读器友好、颜色对比度 ≥ 4.5:1）
- **FR-016**: 选择器在键盘操作时必须显示可见的焦点指示器
- **FR-017**: 系统必须在 JavaScript 禁用时提供基本的语言/货币切换降级方案
- **FR-018**: 翻译键值缺失时，系统必须回退到默认语言（英语）对应文本，不显示空白或键名
- **FR-019**: 货币汇率数据不可用时，系统必须回退到店铺默认货币
- **FR-020**: 商家必须能在主题编辑器中配置语言选择器的位置（header 或 footer）和显示样式
- **FR-021**: 商家必须能在主题编辑器中配置货币选择器的位置（header 或 footer）和显示样式

### Key Entities

- **Language Preference**: 用户当前选择的界面语言标识码（如 `en`、`zh-CN`、`fr`），存储在客户端，具有过期时间
- **Currency Preference**: 用户当前选择的货币代码（如 `USD`、`EUR`、`CNY`、`JPY`），存储在客户端，具有过期时间
- **Geolocation Recommendation**: 基于用户 IP 检测结果生成的推荐语言 + 货币组合，附带已读/未读状态标记
- **Translation Set**: 每种语言的键值对集合，映射翻译键到对应语言文本，缺失键回退到默认语言
- **Available Locale**: 店铺在 Shopify 后台启用的语言和货币组合配置

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户从进入店铺到完成语言切换平均时间不超过 3 秒（包含页面刷新）
- **SC-002**: 用户从进入店铺到完成货币切换平均时间不超过 3 秒（包含价格刷新）
- **SC-003**: 切换语言后，100% 的用户可见文本正确翻译（无空白、无键名暴露）
- **SC-004**: 切换货币后，100% 的价格显示正确货币符号和按汇率转换后的数值
- **SC-005**: 回访用户的偏好识别成功率达到 95% 以上（cookie 未被清除前提下）
- **SC-006**: 语言/货币选择器通过 WCAG 2.1 AA 自动化检测
- **SC-007**: 使用屏幕阅读器完成语言切换操作不超过 15 秒
- **SC-008**: JavaScript 禁用时，语言和货币切换功能仍然可用
- **SC-009**: 非英语访客的页面跳出率相比实施前降低至少 10 个百分点
- **SC-010**: 非默认货币用户的加购转化率不低于默认货币用户（差值 ≤ 5%）

## Assumptions

- 店铺已在 Shopify 后台启用了 Shopify Markets 功能（多货币基础能力）
- 店铺主题是支持 Online Store 2.0 的 Liquid 主题
- 语言翻译文件（`locales/`）已由商家或翻译团队预先准备好
- 汇率转换由 Shopify 平台自动处理，主题负责调用平台 API 获取转换后价格
- 地理位置检测依赖 Shopify 平台或第三方服务，主题不实现 IP 检测逻辑本身
- 偏好数据存储在浏览器端（cookie 或 localStorage），不需要服务端用户账户支持
- 目标浏览器覆盖最新两个版本的 Chrome、Firefox、Safari、Edge
- 移动端和桌面端使用相同的选择器组件，通过响应式设计适配
